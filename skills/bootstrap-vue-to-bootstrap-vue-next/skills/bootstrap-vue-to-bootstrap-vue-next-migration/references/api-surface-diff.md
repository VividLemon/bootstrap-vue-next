# API surface diff (automated, per component)

Generated by parsing BootstrapVue 2.23.1 source + component `package.json` meta (pinned commit `9a246f45`) and
BootstrapVueNext TypeScript prop/emit/slot interfaces (`packages/bootstrap-vue-next/src/types`, pinned commit `07767892`, v1.2.2).

**Re-verified (Nov 2026)** against the runtime props of the published bootstrap-vue 2.23.1 package and the fully resolved
(inheritance included) interfaces of bootstrap-vue-next v1.2.4. That pass corrected the BTable/BTableLite slot columns and
the BNavItemDropdown row (the original parser missed template-literal slot keys and reused prop interfaces), removed one
stray entry, and added props the first pass missed (router-link props, `html-field`, card sub-component props, …).
The prop column now matches both libraries exactly; slot and event columns were checked only where a new
interface exists.

**How to read this:**

- `Old props not found in new` = a prop that exists in BootstrapVue but no prop with the same (case/dash-insensitive) name exists on the target. It was removed, renamed, or turned into a slot / v-model modifier / native attribute.
- ⚠ = the name is **not mentioned anywhere** in the upstream migration guide for that component. These are the most likely silent breakages; look them up in the new docs before rewriting.
- Old events missing in new are often native DOM events (`input`, `change`, `blur`, `click`) that now fall through as attributes in Vue 3 — they usually still work. Check `native-events.md`.
- `BNavItemDropdown` uses `BDropdownProps`/`BDropdownEmits` in BootstrapVueNext; `BTable`/`BTableLite` keep the dynamic `cell(key)`/`head(key)`/`foot(key)` slots and their `()` fallbacks.
- Names that differ only by case/dash are treated as the same prop here, but **`sub-title*` → `subtitle*` on BCard/BCardBody is a real rename** (`sub-title` camelizes to `subTitle`, which is not `subtitle`). See `guide-corrections-and-gaps.md` item 6.
- `id`, `alt`, `form`, `aria-*` entries usually still work as fallthrough HTML attributes rather than props.
- The parser is best-effort: spread props in the old source that were not in its meta (e.g. `id`) and some generic TS types may be missed. Treat as a checklist, not proof.

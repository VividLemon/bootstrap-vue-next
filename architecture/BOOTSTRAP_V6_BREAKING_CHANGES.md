# Bootstrap v6 Breaking Changes Ledger

Every user-facing breaking change between bootstrap-vue-next **1.2.4** (the last 1.x release before the v6 work, commit `1c657d372`) and the Bootstrap v6 release, one row per change.

This file is the source for:

- the user-facing migration notes in `apps/docs/src/docs/migration-data/**`, and
- the bootstrap-vue-next v1 → next migration skills (the follow-up to the BootstrapVue → BootstrapVueNext skill from [#180](https://github.com/VividLemon/bootstrap-vue-next/pull/180)).

A change that is not in this file will not reach users. Write it down even when it seems obvious from the diff.

**Backfill (2026-11-20):** the rows below Pending were reconstructed for everything merged into `bootstrap-v6` up to `5d397b0b1`, by comparing the source of `1c657d372` and `origin/bootstrap-v6` component by component (types, templates, SCSS, exports) and cross-checking the PR descriptions. Where a PR description disagreed with the source, the source won (for example #166 describes intermediate names; the 1.x names are `variant` / `bgVariant` / `textVariant`). The first color commit `641959ec1` has no PR number; its rows cite it with #162 / #164. Rows marked "(verify)" were not confirmed in a browser or against Bootstrap's CSS.

## Rules

- **The PR that makes a breaking change adds its rows here, in the same PR.** A PR with only additive changes adds nothing (its new features belong in the docs, not here).
- **What counts:** a renamed, removed or newly required prop, slot, emit or exposed member; a changed type or value shape; a changed default; changed rendered markup or classes that users may target in CSS or tests; changed behavior or event order/timing; a removed or renamed component, composable, directive, type or export; a dependency or peer dependency change consumers must act on.
- **What doesn't:** internal refactors with no user-facing effect (for example which library runs underneath a component). If it might look breaking but isn't, say so in the PR, not here.
- **One row per change**, under the component it affects. Changes that apply to many components (color objects, `*Attrs`, transitions, breakpoints) get one row under [Global](#global) **and** a concrete row under each affected component, because the skill works per component.
- **Columns:**
  - **Change:** a short description.
  - **Before (1.x) / After:** the exact API in backticks (`variant="danger"` → `:color="{theme: 'danger'}"`), or `— (removed)`.
  - **Migration:** one of
    - `rename`: mechanical find and replace;
    - `rewrite`: mechanical, but the value's shape changes;
    - `manual`: needs judgment (say what to look at);
    - `removed`: no replacement (say what to use instead, if anything);
    - `behavior`: no code change needed, but behavior or markup differs; users should verify.

    A short note may follow the keyword.

  - **PR:** the fork PR (`#165`), or `—` if it predates PRs.
- Mark anything uncertain with "(verify)" in the Change column rather than leaving it out.
- When a later PR changes something again, edit the existing row so it shows 1.x → final, and list both PRs.
